# 算法改进与模型扩展方案

## 一、算法改进方案（针对现成 NSGA-II 的质疑）

现有多目标求解使用标准 NSGA-II，算法本身不构成创新点。计划在三个方面做问题特定的改进：

**1. 热点聚类引导初始化。** 先对当前场景的用户（或热点群组中心）做聚类，以群组中心生成一批初始航路点解，其余个体随机采样。热点场景下最优轨迹通常围绕用户密集区展开，聚类初始化能显著提高初始解质量，缩短收敛代数。该思路来自灾后智能电网的聚类增强 MOPSO 工作。

**2. 自适应变异算子。** 根据种群多样性或收敛停滞程度动态调整多项式变异的分布指数：收敛停滞时增大变异强度以跳出局部最优，接近收敛时减小变异强度以精化解。该思路来自改进 NSGA-II 的多无人机目标分配工作。

**3. 速度约束修复算子。** 对违反最大飞行速度约束的个体，沿航段方向做投影修复，把航段长度缩放到允许范围内，而不是直接淘汰。修复后可行解比例提高，搜索效率更好。

可选增强：用轻量学习模型（如 Q 学习）根据历史进化信息选择变异强度，作为算法改进的扩展点。

## 二、评价指标

| 指标 | 含义 | 用途 |
|---|---|---|
| 超体积 HV | Pareto 前沿与参考点围成的体积 | 综合衡量收敛性与分布性 |
| 反转世代距离 IGD | 前沿到参考前沿的平均距离 | 衡量逼近真实前沿的程度 |
| 间距 Spacing | 前沿解分布的均匀程度 | 衡量多样性 |
| 收敛代数 | 达到给定 HV 所需代数 | 衡量收敛速度 |
| 运行时间 | 单次求解耗时 | 衡量计算复杂度 |
| Pareto 解数量 | 非支配解个数 | 衡量解的丰富程度 |

| 算法 | 角色 | 说明 |

## 四、模型扩展：资源分配与能耗

**带宽分配（OFDMA 视角）**：为每个用户引入带宽变量 B_k，满足 Σ_k B_k ≤ B，用户速率为 R_k = B_k log2(1 + γ_k)。该扩展使问题从 12 维升至高维混合整数规划，标准元启发式难以直接求解，需要使用分解或松弛方法。

**时隙分配（TDMA 视角）**：为每个用户引入时间变量 τ_k，满足 Σ_k τ_k ≤ T，用户时间平均速率为 (τ_k / T) R_k。

**能耗模型**：采用旋翼无人机推进功耗模型，功耗由诱导功率、叶型功率与寄生阻力功率三部分构成，随飞行速度变化；总能耗为各时隙功耗之和。可直接引用 Zeng & Zhang（IEEE TWC 2017）与 Ding 等（IEEE TWC 2020）的模型形式。

**分级 QoS 约束**：对关键用户施加 R_k ≥ R_min 或中断概率约束，保证救援与求救业务的服务底线。

## 五、多无人机扩展方案

| 项目 | 单机（当前） | 多机（扩展） |
|---|---|---|
| 决策变量 | 6 个航路点 × 2 = 12 维 | N 架 × 6 个航路点 × 2 = 12N 维 |
| 接入变量 | 无 | 二值关联 a_{k,m}，每用户接入一架 |
| 约束 | 区域边界、最大速度 | 增加最小机间距、覆盖约束、接入唯一性 |
| 目标 | 吞吐 + 最差用户 QoS | 不变，可增加能耗或能效目标 |
| 求解 | NSGA-II | 分解式算法（轨迹子问题 + 接入子问题交替） |

## 六、三类求解方法对比

| 方法 | 代表文献 | 优点 | 缺点 | 本课题建议 |
|---|---|---|---|---|
| 凸优化 / 交替优化 | Zeng 2017；Wu 2018 | 有收敛性保证、复杂度可控 | 需要问题可凸化，概率视距与最小速率目标难处理 | 作为期刊版对照或子问题求解器 |
| 多目标进化算法 | Deb 2002；Ali 2025；Yang 2025 | 一次得到 Pareto 前沿、对非凸非光滑问题鲁棒 | 无收敛性证明、参数敏感 | 当前主线，需加入问题特定改进 |
| 深度强化学习 | Ding 2020；He 2023 | 适合在线与未知环境 | 训练成本高、可复现性差、难以给出权衡前沿 | 作为未来在线版本或对比方法 |

## 七、代码实现路线

1. `module_scenarios.py`：定义郊区、城区、密集城区三套信道与移动参数；
2. `weighted_objectives.py`：实现加权 max-min 目标与分级 QoS 约束；
3. `resource_allocation.py`：实现带宽/时隙分配子问题；
4. `energy_model.py`：实现旋翼能耗模型；
5. `nsga2_improved.py`：实现聚类初始化、自适应变异与约束修复；
6. `multi_uav_pareto.py`：多无人机与用户接入的联合优化。

上述模块按顺序实现，每一步都能独立产出可对比的实验结果，避免一次性改动过大。
