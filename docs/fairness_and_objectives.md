# 公平性目标与优化目标设计

## 一、四类公平性目标

设第 k 个用户在第 t 个时隙的速率为 R_k(t)，用户数为 K，时隙数为 T。

**1. 总速率最大化（Sum-rate）**

```
max  f_sum = (1/T) * Σ_t Σ_k R_k(t)
```

含义：只追求系统吞吐。优点是实现简单、吞吐最高；缺点是资源向信道好的用户集中，边缘用户可能得不到服务。

**2. 公平指数最大化（Jain's fairness index）**

```
J(t) = (Σ_k R_k(t))^2 / ( K * Σ_k R_k(t)^2 )
max  f_J = (1/T) * Σ_t J(t)
```

含义：让用户之间的速率尽可能均匀（取值 1/K 到 1）。优点是直观、无量纲；缺点是只看相对分布，不体现绝对速率高低，也可能把资源分给低需求用户。

**3. 最大最小公平（Max-min）**

```
max  f_min = (1/T) * Σ_t min_k R_k(t)
```

含义：抬高最差用户的服务水平，保障服务质量底线。优点是直接对应“不落下任何用户”；缺点是单个极差用户会主导优化结果。

**4. 比例公平（Proportional fairness）**

```
max  f_pf = (1/T) * Σ_t Σ_k log( R_k(t) )
```

含义：在效率与公平之间取折中，是通信系统中最常用的调度目标。优点是兼顾吞吐与公平、天然带有“边际效用递减”；缺点是需要正速率，且不直接对应最差用户保障。

## 二、四类目标对比

| 目标 | 优化对象 | 优点 | 缺点 | 适用场景 |
|---|---|---|---|---|
| 总速率 | 系统吞吐 | 吞吐最高、易实现 | 边缘用户被牺牲 | 尽力而为业务 |
| 公平指数 | 速率分布均匀度 | 直观、可比 | 不反映绝对水平 | 统计公平性评价 |
| Max-min | 最差用户 | 保障服务底线 | 可能牺牲较多吞吐 | 应急、救援 |
| 比例公平 | 效率与公平折中 | 兼顾两者 | 不直接保障底线 | 通用调度 |

## 三、本课题采用的加权 Max-min

应急场景中不同用户的重要性不同，因此采用加权形式：

```
max  f_wmin = (1/T) * Σ_t min_k ( R_k(t) / w_k )
```

其中 w_k 为用户 k 的优先级权重。取所有 w_k = 1 时退化为标准 max-min 公平；取分级权重时实现按重要性的资源分配。配套的吞吐目标保持不变：

```
max  f_sum = (1/T) * Σ_t Σ_k R_k(t)
```

两个目标构成双目标优化问题，通过 Pareto 前沿展示“吞吐—服务质量”的折中关系。

## 四、应急场景的优先级权重设计

| 用户类别 | 业务特征 | 建议权重 w_k | 说明 |
|---|---|---|---|
| 救援队与指挥 | 高清视频回传、指挥调度 | 3.0 | 带宽需求高、时延敏感 |
| 被困人员 | 求救信息、位置上报 | 2.0 | 速率需求低但必须接入 |
| 普通用户 | 社交通信、尽力而为 | 1.0 | 在资源允许时服务 |

也可以采用两级策略：第一阶段只保障关键用户的速率门限（硬约束），第二阶段在剩余资源中提升普通用户的最差速率。

## 五、分级 QoS 约束的形式

除加权目标外，还可以把关键用户的服务质量写成硬约束：

```
R_k(t) >= R_min^(c),  ∀ k ∈ 类别 c, ∀ t
```

对应到优化问题中，用不等式约束 g = R_min^(c) − R_k(t) ≤ 0 表示；若允许少量违约，可改写为中断概率约束：

```
Pr( R_k(t) < R_min^(c) ) <= ε
```

## 六、与现有代码的对应关系

| 现有实现 | 位置 | 改造方式 |
